# 教程：从零写第一个扩展

> 全程约 15 分钟。每一步都可运行、可验证，不需要任何第三方依赖。
>
> 读完你将得到一个**能工作**的扩展：它会在服务端记录访问日志，
> 并在客户端给"今天更新过的文件"打上一个徽章。

[← 返回文档首页](README.md) · [← 返回主文档](../NavExt.md)

---

## 0. 先弄清"扩展"是什么

NavExt 的扩展就是一个**目录**，放在站点的 `.js/` 下：

```
你的站点/
├── server.js
├── .navext.client.js
├── .js/                     ← 扩展都放这里
│   ├── js.list.json         ← 扩展清单
│   └── my-first-ext/        ← 我们要做的扩展
│       ├── mod.json         ← 元数据（名称、作者、顺序）
│       ├── js.json          ← 注入配置（样式、脚本、配置项）
│       ├── index.js         ← 服务端钩子（可选）
│       ├── client.js        ← 客户端脚本（可选）
│       └── styles.css       ← 样式（可选）
```

**最小可用扩展只需要两个文件**：`mod.json` + 一个 `index.js` 或 `client.js`。

---

## 1. 建目录 + 登记

```bash
mkdir -p 你的站点/.js/my-first-ext
```

> ⚠️ **目录名必须以字母或下划线开头**（正则 `/^[a-zA-Z_][a-zA-Z0-9_-]{0,63}$/`）。
> 像 `01-my-ext` 这样数字开头，扩展**能加载**，但配置/统计接口会返回
> `{"error":"id 不合法"}` —— 这是个容易踩的坑，记住它。

然后在 `.js/js.list.json` 里登记（没有就新建）：

```json
{
  "extensions": ["my-first-ext"]
}
```

> 也可以直接跑 `node cli.js create my-first-ext` 让 CLI 交互式生成骨架，
> 但本教程手写一遍，你能看清每个文件的作用。

---

## 2. 写 `mod.json`

```json
{
  "name": "我的第一个扩展",
  "description": "记录访问日志，并标记今天更新过的文件",
  "version": "1.0.0",
  "author": "你的名字",
  "enabled": true,
  "order": 100
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 显示名称，不填则用目录名 |
| `description` | 扩展说明 |
| `version` / `author` | 版本、作者 |
| `enabled` | `false` 时跳过加载 |
| `order` | 数字越小越先执行，默认 100 |
| `requires` | 依赖的扩展 ID 数组（v2.3），缺依赖会被跳过 |

> **注意**：`mod.json` **没有** `id` 字段 —— 扩展 ID 就是**目录名**。

到这里，重启（或刷新）服务，扩展就已经被加载了，只是还不干任何事。
可以访问 `GET /api/extensions` 确认它在列表里。

---

## 3. 服务端：第一个钩子

新建 `index.js`：

```js
'use strict';

/**
 * 服务端钩子 —— 运行在 Node 里，能读写文件、发网络请求。
 * 所有钩子都可以是 async，内核统一 await。
 */

function onInit(ctx) {
  // ctx 是你的"上下文"：配置、目录、日志工具都在这里
  ctx.log('✅ 我的第一个扩展已启动');
  ctx.log('   扩展目录：', ctx.extDir);
  ctx.log('   站点根目录：', ctx.root);
}

module.exports = { onInit };
```

保存后**不用重启**（NavExt 有热重载，见 [08 运行机制](08-运行机制.md)），
刷新页面或看服务端终端，应该能看到这两行日志：

```
  [ext:my-first-ext] ✅ 我的第一个扩展已启动
  [ext:my-first-ext]   扩展目录：/你的站点/.js/my-first-ext
```

**恭喜，第一个钩子跑通了。** `ctx.log` 会自动带上 `[ext:你的ID]` 前缀，
方便在多个扩展共存时区分。

## 4. 服务端：埋点统计

把 `index.js` 升级一下，加一个 `onResponse` 钩子 —— 它在响应发出后被调用，
适合做计数、日志、慢请求告警：

```js
'use strict';

const hits = new Map();          // pathname -> 访问次数
let startedAt = Date.now();

function onInit(ctx) {
  startedAt = Date.now();
  ctx.log('✅ 启动完成');
}

/* 响应发出后触发。注意：返回值被忽略，签名是 (info, ctx)。
 * info = { method, pathname, url, status, bytes, durationMs, headers }
 */
function onResponse(info, ctx) {
  // 只统计成功访问的页面，跳过 API 和静态资源
  if (info.status >= 400) return;
  if (/^\/api(\/|$)/.test(info.pathname)) return;

  hits.set(info.pathname, (hits.get(info.pathname) || 0) + 1);

  // 慢请求（超过 100ms）额外提醒
  if (info.durationMs > 100) {
    ctx.warn('慢请求：', info.pathname, info.durationMs + 'ms');
  }
}

/* 被 GET /api/extensions/my-first-ext/stats 查询时同步返回，用于暴露指标。
 * ⚠️ 必须同步 —— 返回 Promise 会被内核拒绝（500 错误）。
 *
 * ⚠️ 键归一化：onResponse 的 info.pathname 是「URL 路径」（/docs/a.html、首页 /），
 *    而客户端 getFiles()[].path 是「相对路径」（docs/a.html、首页 index.html）。
 *    两者对不上，客户端会永远匹配不到 —— 所以这里统一下发相对路径。
 */
function stats(ctx) {
  const toRel = (p) => (p === '/' ? 'index.html' : p.replace(/^\/+/, ''));

  const sorted = [...hits.entries()].sort((a, b) => b[1] - a[1]);

  const counts = {};
  for (const [pathname, count] of sorted) counts[toRel(pathname)] = count;

  return {
    startedAt,
    uptimeMs: Date.now() - startedAt,
    totalHits: sorted.reduce((n, [, c]) => n + c, 0),
    counts,                                          // 相对路径 → 次数
    top: sorted.slice(0, 10).map(([pathname, count]) => ({ pathname, count })),
  };
}

module.exports = { onInit, onResponse, stats };
```

验证：

```bash
# 先访问几次页面
curl -s http://localhost:3000/ > /dev/null
curl -s http://localhost:3000/ > /dev/null

# 再看统计
curl -s http://localhost:3000/api/extensions/my-first-ext/stats
```

返回类似：

```json
{
  "id": "my-first-ext",
  "stats": {
    "startedAt": 1791188686000,
    "uptimeMs": 52341,
    "totalHits": 2,
    "counts": { "index.html": 2 },
    "top": [{ "pathname": "/", "count": 2 }]
  }
}
```

> **服务端资源请用 `ctx.timer` / `ctx.interval`，不要用原生 `setInterval`。**
> 内核托管的定时器会在扩展重载 / 禁用时**自动清理**，用原生的会泄漏。
> 取消用 `ctx.clearTimer(handle)`。

## 5. 客户端：给卡片加徽章

服务端只管数据和响应；**要改页面上看到的东西，得写客户端脚本**。

新建 `js.json` 声明要注入的文件：

```json
{
  "styles": "styles.css",
  "scripts": "client.js"
}
```

新建 `client.js`：

```js
'use strict';

(function () {
  var EXT_ID = 'my-first-ext';

  /* 卡片是内核渲染的。要装饰它，必须等 'cards-rendered' 事件。
   * 视图切换、搜索都会重新渲染，所以要写"幂等"的代码 —— 重复执行安全。
   * addCardBadge 用 key 去重，天然幂等。
   */
  function decorate() {
    var DAY = 86400000;

    NavExt.getFiles().forEach(function (f) {
      // 今天更新过的文件，打一个"新"徽章
      if (Date.now() - f.mtime < DAY) {
        NavExt.addCardBadge(f.path, '新', '#10b981', { key: 'new-badge' });
      }
    });
  }

  NavExt.on('cards-rendered', decorate);
  NavExt.on('view-changed', decorate);

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', decorate);
  } else {
    decorate();
  }
})();
```

新建 `styles.css`：

```css
/* 用 CSS 变量，跟随用户切换的主题色自动变化 */
.nx-new-card {
  border-color: var(--brand) !important;
}
```

保存，刷新页面 —— 今天改过的文件卡片上会出现绿色的「新」徽章。

## 6. 客户端：把服务端统计显示出来

服务端的 `stats()` 数据，客户端用 `NavExt.getExtStats(id)` 取回（异步）：

```js
function paintStats(stats) {
  if (!stats) return;

  // stats.counts 的键是"相对路径"；getFiles()[].path 也是相对路径，能直接对上。
  // 但为了万无一失，统一走 normalizePath 归一化（大小写、斜杠差异都能抹平）。
  var counts = {};
  Object.keys(stats.counts || {}).forEach(function (k) {
    counts[NavExt.normalizePath(k)] = stats.counts[k];
  });

  NavExt.getFiles().forEach(function (f) {
    var n = counts[NavExt.normalizePath(f.path)];
    if (n) NavExt.addCardBadge(f.path, '👁 ' + n, 'rgba(127,127,127,.18)', { key: 'hits' });
  });
}

function refresh() {
  if (NavExt.isDisposed(EXT_ID)) return;      // 已清理就别再发请求
  NavExt.getExtStats(EXT_ID).then(paintStats).catch(function () {});
}
```

但服务端 `stats()` 返回的 `top` 用的是 **URL 路径**（`/docs/a.html`），
而 `getFiles()[].path` 是**相对路径**（`docs/a.html`）—— 两套体系对不上，
直接当键用会**永远匹配不到**。这是最容易踩的坑之一。

**NavExt 从 v2.7 起提供了归一化工具**：

```js
NavExt.urlToRel('/docs/a.html')   // → 'docs/a.html'
NavExt.urlToRel('/')              // → 'index.html'
NavExt.relToUrl('index.html')     // → '/'
NavExt.normalizePath('/DOCS/A.HTML')   // → 'docs/a.html'（可比较的 key）
NavExt.pathOf('docs/a.html')      // → '/docs/a.html'（统一到 URL 体系）
```

服务端也有一份同名同行为的（经 `ctx` 调用）：`ctx.urlToRel()`、`ctx.relToUrl()`、`ctx.pathOf()`。

## 7. 客户端：别忘了清理

客户端脚本里如果用 `setInterval`、`addEventListener`、轮询 `fetch`，
**扩展被禁用或页面关闭后它们不会自动停**。用 `NavExt.disposer` 托管：

```js
var timer = setInterval(refresh, 30000);
var offCards = NavExt.on('cards-rendered', refresh);

NavExt.disposer(EXT_ID, function () {
  clearInterval(timer);
  offCards();
});
```

内核会在这些时机自动执行你注册的清理函数：
- `pagehide` / `beforeunload`（页面关闭、跳转、进 bfcache）
- 手动调用 `NavExt.dispose(EXT_ID)`

配套 API：

| 方法 | 说明 |
| --- | --- |
| `NavExt.disposer(extId, fn)` | 注册清理函数，返回取消注册的函数 |
| `NavExt.dispose(extId)` | 手动清理（幂等，不重复执行），并移除该扩展注入的 CSS |
| `NavExt.isDisposed(extId)` | 是否已清理 |

> 服务端对称能力：`onDispose(ctx)` 钩子，在扩展重载 / 禁用 / 关停时被调用。

## 8. 完整的 `client.js`（把上面几步合起来）

```js
'use strict';

(function () {
  var EXT_ID = 'my-first-ext';
  var DAY = 86400000;

  function decorate() {
    NavExt.getFiles().forEach(function (f) {
      if (Date.now() - f.mtime < DAY) {
        NavExt.addCardBadge(f.path, '新', '#10b981', { key: 'new-badge' });
      }
    });
  }

  function paintStats(stats) {
    if (!stats || !stats.counts) return;
    var counts = {};
    Object.keys(stats.counts).forEach(function (k) {
      counts[NavExt.normalizePath(k)] = stats.counts[k];
    });
    NavExt.getFiles().forEach(function (f) {
      var n = counts[NavExt.normalizePath(f.path)];
      if (n) NavExt.addCardBadge(f.path, '👁 ' + n, 'rgba(127,127,127,.18)', { key: 'hits' });
    });
  }

  function refresh() {
    if (NavExt.isDisposed(EXT_ID)) return;
    NavExt.getExtStats(EXT_ID).then(paintStats).catch(function () {});
  }

  function run() { decorate(); refresh(); }

  var offCards = NavExt.on('cards-rendered', run);
  var offView = NavExt.on('view-changed', run);
  var timer = setInterval(refresh, 30000);

  NavExt.disposer(EXT_ID, function () {
    clearInterval(timer);
    offCards();
    offView();
  });

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', run);
  } else {
    run();
  }
})();
```

## 9. 加一个用户可调的配置项

在 `js.json` 里加 `config`，用户在扩展管理面板里就能改，**不用动代码**：

```json
{
  "styles": "styles.css",
  "scripts": "client.js",
  "config": {
    "badgeColor": {
      "type": "color",
      "label": "新文件徽章颜色",
      "default": "#10b981"
    },
    "freshHours": {
      "type": "number",
      "label": "多少小时内算「新」",
      "description": "默认 24 小时",
      "default": 24,
      "min": 1,
      "max": 720,
      "step": 1
    }
  }
}
```

服务端读：`ctx.config.badgeColor`（已合并默认值与用户覆盖），
用户显式覆盖的部分在 `ctx.userConfig`。
客户端读：`NavExt.getExtConfigField(EXT_ID, 'badgeColor')`。

```js
// client.js 里改成读配置
var color = NavExt.getExtConfigField(EXT_ID, 'badgeColor') || '#10b981';
var hours = Number(NavExt.getExtConfigField(EXT_ID, 'freshHours')) || 24;
if (Date.now() - f.mtime < hours * 3600000) {
  NavExt.addCardBadge(f.path, '新', color, { key: 'new-badge' });
}
```

支持的类型：`boolean` / `number` / `string` / `color` / `select`。

## 10. 用 `vm.js` 自查安全性

写完了，跑一遍扩展安全审计：

```bash
cd 你的站点
node vm.js .js/my-first-ext
```

输出会给出三级评级之一：

| 评级 | 分数 | 含义 |
| --- | --- | --- |
| `Benign` | 76–100 | 未发现越界行为 |
| `Suspicious` | 31–75 | 有可疑调用（动态 require、外联、写系统路径等） |
| `Malicious` | 0–30 | 确认有害（读 SSH 密钥、写 crontab、反弹 shell 等） |

`vm.js` 用纯 `vm` 仿真运行你的代码，**不会真实执行**恶意操作
（有金丝雀文件验证零副作用）。详细机制见 [09 安全边界](09-安全边界.md)。

批量审计：

```bash
node vm.js --all .js
```

## 11. 调试清单

扩展不生效时，按顺序排查：

| 现象 | 检查 |
| --- | --- |
| 完全没反应 | `.js/js.list.json` 里登记了吗？目录名是否字母开头？ |
| 服务端日志无输出 | `index.js` 的 `module.exports` 导出了对应函数吗？ |
| 改了没生效 | 等 1 秒（扩展 TTL 1000ms），或刷新页面；`?fresh=1` 强制刷新 |
| 配置/统计接口报 `id 不合法` | 目录名以数字开头了 |
| 客户端脚本没跑 | `js.json` 的 `scripts` 字段写了吗？打开浏览器控制台看报错 |
| 徽章不显示 | 卡片的 path 与你的键对上了吗？用 `normalizePath` 归一化 |
| 扩展互相干扰 | 用 `order` 控制加载顺序；用 `requires` 声明依赖 |
| 请求 404 | 扩展**不能**占用 `/api/*`（内核自留），请用自己的前缀 |
| 钩子卡住 | 异步钩子默认 5s 超时（可配 `extensions.timeout`） |

打开浏览器控制台，NavExt 的警告都带 `[NavExt]` 前缀。
